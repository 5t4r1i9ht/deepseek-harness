# Agent Note: 浏览器提问通知

Status: implemented

[English](2026-09-03-browser-question-notifications.md) | 中文

## 问题

用户切换到其他标签页或应用时，agent（智能体）可能一直等待回答。对话和侧栏指示器需要用户持续查看 Web 页面。

## 决策

`dsh-client-ui-question-notifications` 观察 `ui-session` 拥有的当前生效待处理交互数据源。浏览器授予通知权限后，插件为问题和计划审阅发送通知。通用设置按钮通过用户主动点击请求权限。权限仍由浏览器拥有，因为它作用于一个来源和浏览器，独立于共享同一 Harness home 的其他客户端。

通知包含本地化通用文案，避免在桌面显示问题内容。点击会打开发起请求的 Session（会话），但不会回答问题。每个请求对象在一次插件生命周期内通知一次；请求结束、当前生效请求被替代或插件资源释放都会关闭通知。资源释放后到达的权限响应不会产生副作用。

同一个包也是可安装的 profile（配置档）组合包：其 patch 插入通知行，预构建压缩包包含两个运行时入口。通过 GitHub Release 分发时，安装指南作为单独附件提供。安装和启动说明固定使用 DSH `0.1.2-rc.1`，该版本提供所需的 Client（客户端）服务；`0.1.1-rc.2` 客户端不受支持。保留现有包名可以保持浏览器模块 id 一致，无需维护第二套分发实现。

[待处理交互归属决策](../architecture/2026-08-20-client-session-conversation-ownership.zh.md) 仍是权威。本功能增加了一个 Consumer（消费者），没有取代其中的归属或生命周期规则。

## 考虑过的替代方案

**拦截提问 waterfall（瀑布链）。** 通知不会回答请求。观察现有生效 UI 数据源可以避免依赖回答者顺序，并使提醒与用户当前可以回答的请求一致。

**从助手文本或回放日志推断问题。** 这些来源无法区分可操作的实时问题与普通文本或已完成历史。待处理数据源已经记录了可回答状态。

**推送通知和共享 Host（宿主）偏好。** 关闭页面后的通知发送需要单独的订阅和 service worker 生命周期。Host 偏好无法授予浏览器权限，因此本插件限定为页面打开期间的桌面通知。

## 后果

此功能通过组合接入，无需更改 agent loop（智能体循环）、模型 schema 或 Session 日志。操作系统与浏览器策略仍控制最终呈现。不同标签页和插件重载可能提醒同一个未回答问题；去重有意限定在单个插件实例内。

包内测试覆盖权限失败、延迟权限响应、问题替换、点击导航和副作用资源释放。录制的 question-composer 场景运行真实 Web 组合，仅将外部桌面 Notification API 替换为探针。
